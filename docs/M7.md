# M7：官方 study runner + 树入口

Will 于 2026-08-22 锁定。本里程碑把 **scan → playFromProbePlan → applyHumanReview → generateAll** 收成一条官方 runner，并把夹具的导航树入口纳入同一条 Probe 序列。

四套公共接口与六步不变：`SourceProvider` / `ProjectAdapter` / `DiscoveryAdapter` / `AgentRunner`；`detect` / `plan` / `start` / `scan` / `explore` / `execute`。

`runClosedLoop` **不是**第五套接口。它是 review 包里与 `applyHumanReview` 同层的函数。`playFromProbePlan` 仍是 helper。

**不**增加 Explorer、GUI Agent、Effect DAG，也 **不** 写入 Rocket.Chat 专用选择器 / 类型 / 路由。  
**不**改写 `ProjectAdapter.start`。  
**不**把 create-channel 做成产品旅程；那是本 PR 之后的下一深化域，沿用同一 runner。

> CI 夹具仍是登录墙 + 撰写 + 列表，外加一条打开撰写面的导航树入口。这不是产品 RC 证明。  
> 产品 RC 证明是后续由可信操作者完成的运行，不是 CI。

## runClosedLoop

签名（概念上）：

`runClosedLoop({ analysisRoot, runId, project, context, reviewSpec }) -> { play results, reviewed model, generated paths }`

必须按此顺序调用：

1. **scan**：若本 run 已有 `evidence/static.jsonl` **且** `candidates.jsonl`，跳过 scan；否则 `DefaultDiscoveryAdapter.scan`。scan 仍不依赖 `StartResult`。
2. **playFromProbePlan**（已有 helper）：从 `analysisRoot` 加载人类批准的 `probe-plan.yaml`，在**一个**共用会话上按序 play。
3. **applyHumanReview(reviewSpec)**
4. **generateAll**

禁止：

- 调用 `ProjectAdapter.start`
- 调用 `explore()` 去做产品动作
- 发明 bindings
- 把 `proposals/` 当 bindings 读
- 把 Probe 拆成 N 次孤立 `execute()`

可选的薄 `packages/cli` bin 只允许转发给 `runClosedLoop`；不是本里程碑的交付要求。

## 夹具树入口

仍是同一套登录墙 + 撰写 + 列表夹具，**不**增加第三套夹具应用。

增加一条导航 / 入口控件，点击后打开撰写面（夹具里的树入口类比）。人类绑定：**nav/entry、composer、submit**。

`ProbePlan.actions` **必须**是：

```
[
  { binding_id: nav, action: click },
  { binding_id: composer, action: type, value },
  { binding_id: send, action: submit 或 click }
]
```

`send_action` 等于最后发送步的 binding。`entry` 字段保持不变。

仓库内夹具的 `probe-plan.yaml` 可以仍然省略 `actions`（旧文件按单步 `send_action` + `click` 解释）。官方 M7 路径由 runner / 测试写入上述三步。

## 契约测试

保持 M0–M6b 变绿。`npm test` = vitest + tsc。

- storageState 绕过登录
- 人类 bindings 使用 accessibility / role+name，**不是** `#control-send`
- `runClosedLoop` 在一个会话里 play：nav click + type + submit
- `applyHumanReview` 的 retarget 保持同一个 `journey_id`
- `generateAll` 发出的 spec 按顺序包含 **三条** 已批准 locator；没有 `#control-send`
- grep `packages/`：不把 Rocket.Chat / Room / Channel 当核心类型；不写死 `usernameOrEmail`、`/channel/`、`study-send`、`aria-label=Send`

## 夹具不是 RC 证明

本夹具只证明官方 runner 与树入口合约。产品 RC 证明是后续操作者运行：

1. `explore` 倒出 tree + composer + send
2. 人类写入 bindings
3. `runClosedLoop` play：tree-open + type + send
4. retarget 保持 `jny-send`
5. 三条已批准 locator
6. 房间里出现唯一消息

Create-channel 是本 PR **之后**的下一深化域，沿用同一 runner，不是本 PR。
