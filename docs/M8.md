## Journey.entry_url

Journey 可有可选 `entry_url`。

`applyHumanReview` 的 **addJourney** 与 **retarget** **必须**在该 study 的 `run-context.yaml` 存在 `entry_url` 时，把它拷到对应旅程上。

`hydrateModel` **不得**发明 `entry_url`。

`generateTests`：

- 若旅程有 `steps` **且** 有 `entry_url`：第一行是 `page.goto(entry_url)`
- 若无 `entry_url`：保持 `about:blank`
- **仍不得**在导出时读取 `probe-plan.yaml` 或 `run-context.yaml`。只读已审定 model。

## addJourney

`HumanReviewSpec.addJourney` 允许首次接受时指定稳定 `journey_id`。

锁定形状：

```
addJourney: [{ journey_id, control_id }]
```

`name` 仍可用于展示；缺省时用 `journey_id`。

- 若该 `journey_id` 已在 model 中：失败或要求 `retarget`，**不得**再造一条重复旅程。
- `control_id` **必须**在该 run 的 `bindings.jsonl` 里有 `approved_by: human` 的绑定。
- 把该 study 人类批准的 `ProbePlan.actions` 拷到 `journey.steps`。
- 创建旅程的 `journey_id` **不是** `jny-send`。

兼容：仍接受单个对象（M0–M7 的 `{ name, control_id }`），也接受数组。

## 夹具创建入口

仍是同一套登录墙 + 撰写 + 列表夹具，**不**增加第三套夹具应用。

增加一条创建入口：打开名称栏 + 提交，提交后导航/列表出现新项。人类绑定覆盖创建序列。

官方 M8 路径使用**新的 study 形分析**（不是发送 study），`ProbePlan.actions` 为：

```
[
  { binding_id: 打开创建, action: click },
  { binding_id: 名称栏, action: type, value },
  { binding_id: 提交创建, action: submit }
]
```

`runClosedLoop` + `addJourney` 使用**新的** `journey_id`（不是 `jny-send`）。  
`generateTests` 发出已批准的创建 locator，并 `goto` 夹具 `entry_url`。  
禁止默认 `#control-send`。`packages/` 不写 RC 字符串。
