- 入口清单：每条已接受旅程的 `entry_url`
- 已发现候选规模：该 run `candidates.jsonl` 行数
- 保留几条：已接受旅程数
- 删了几条：被拒候选数
- 显式 Gap：未审定候选数；每个 `observed === false` 的六列格；若 `static.jsonl` 没有合法记录则 Gap「静态扫描未落盘」

## HumanReviewSpec.annotate

锁定形状：

```
annotate?: Array<{
  journey_id: string;
  affected_parties?: string;
  combinations?: string;
  keep_reason?: string;
}>
```

`applyHumanReview(annotate)`：

- 把给出的字段写到 `model/` 里已有旅程
- 不改 `status`、`steps`、`entry_url`、六列 `observed`
- 未知 `journey_id` 硬失败
- 省略的字段保留模型原值
- `affected_parties` trim 后恰好为「用户」硬失败
- `keep` / `reject` / `confirmEffects` / `retarget` / `addJourney` 保持原样
- `keep_reason` 住在 `annotate`，不在 `KeepJourneySpec`
- `hydrateModel` 不得发明这些字段

Journey 落盘字段：`affected_parties`、`combinations`、`keep_reason`。Schema `additionalProperties: false`，只在属于它们的类型 / journeys yaml schema 增加这些键。

## 控件成为候选

每个 explore 落盘的 Control 必须同时是 `kind: control` 候选：`discovery_key` 为 `control:<control_id>`，`label` 为 `observed.name`（字形不改写），`review_status` 为 `unreviewed`。不得 Top-N 丢弃。按 `discovery_key` 去重。已有 execute 的 control / interaction 候选保留。

`applyHumanReview` 或 `generateAll` 加载某 run 时，若 `controls.jsonl` 有 Control 不在 `candidates.jsonl`，则确定性地追加到该 run 的 `candidates.jsonl`。这不是一次新的 explore。拒绝 control 候选必须有 `rejection_reason`，且不创建旅程。新旅程仍只经 `addJourney` / `retarget`。

## 空 static.jsonl 不得跳过 scan

仅当该产物已有 ≥1 条 schema 合法的 static 记录才跳过 scan。缺失 / 空 / 仅空白的文件必须跑 scan。

## 图与控件节

mermaid 节点标签 = 旅程或能力名。不得为每个 study 焊死 `SendControl`。

产品地图控件节列出已接受旅程的 steps/bindings 引用的每一个 Control。去掉会丢掉树入口的 `/send|发送|submit/` 过滤。不得放出没有 Binding 的残留 `bind-*` 行。

## 契约测试

保持 M0–M16 变绿。`npm test` = vitest + tsc。夹具，不是 RC。

1. 已接受旅程有三步 Binding → 地图正文按顺序列出这些 locator
2. `annotate` 写入 `affected_parties` / `combinations` / `keep_reason` → 地图显示它们；`affected_parties === 「用户」` 使 `applyHumanReview` 失败
3. 省略 `annotate` → 未识别 / 无 / 未写理由
4. 夹具 explore：每个落盘 Control 以 `control:<id>` 出现在 `candidates.jsonl`
5. 加载有 `controls.jsonl` 但缺 control 候选的 run 会提升它们；数量 = controls + 此前非重复候选
6. mermaid 节点 ≠ `SendControl`；等于能力或旅程名
7. Surface.name 为「撰写面」→ 入口节没有「撰写面」，有 `entry_url` 或「未识别」

若测试与本合同冲突，本合同优先。
